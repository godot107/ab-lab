# exp001_demo: readout

*EC2 proof of concept, live 2026-10-03 18:09 UTC to 2026-10-09 14:35 UTC.
Snapshot taken and stack deleted 2026-10-09. Stopped ~28 h before the 7-day
rule; see the amendment in `docs/experiment_design.md`.*

## Findings

1. **The pipeline works.** The split was 108 / 118 (SRM p = 0.51, pass).
   Assignment stayed sticky for every returning synthetic visitor (the
   generator fails loudly if a visitor switches arms), and every drill-through
   traces back to an exposed visitor.
2. **The method recovered a known effect.** 200 of the 226 visitors were
   synthetic (`synthetic_traffic.py --visitors 200 --seed 31`, launch day).
   The planted rates were 30% (A) and 42% (B), a +12 pp lift.

   |  | A | B | Lift | 95% CI | p |
   |---|---|---|---|---|---|
   | Planted (truth) | 30.0% | 42.0% | +12.0 pp | | |
   | Synthetic, observed | 35/96 = 36.5% | 58/104 = 55.8% | +19.3 pp | +5.8 to +32.9 | 0.006 |

   The test correctly called the effect, and the interval covers the true
   +12 pp. The point estimate overshoots, mostly because B drew high. That is
   the winner's curse at this sample size: with an MDE of ~20 pp, a +12 pp
   effect clears significance only when the draw runs high.
3. **Real visitors: inconclusive.** 26 humans across six days (A 5/12 = 42%,
   B 8/14 = 57%; +15 pp, 95% CI −23 to +54 pp, p = 0.43). With this sample,
   the test could only have detected differences of about 50 pp. **This is not
   evidence that the layouts perform the same.** Some of these visits are my
   own checks on launch day (16 of the 26 human exposures are on 2026-10-03),
   so the true outside-visitor count is lower still.
4. **Traffic was the binding constraint.** After launch day the site averaged
   about two human visitors a day, and none arrived after 2026-10-07. A
   LinkedIn post doesn't produce the 500 visitors this design needs.
   The real 28-day `exp001_layout` would need a different traffic source to
   be worth running.

## What the tooling got wrong

- **`report.py` and `brief.py` pool synthetic and human traffic.** Their
  headline (+18.9 pp, p = 0.0045, and "Adopt layout B" in the brief) is
  dominated by the planted effect. The brief does print a "200 of 226 visitors
  were synthetic" banner, but its bottom line still reads as a decision.
  **Fixed (2026-10-09):** with mixed traffic both tools now decide on real
  visitors only and report the synthetic ones as a separate method check.
  Rerun on this snapshot, the brief's bottom line reads "No change … *not*
  evidence that the layouts are equivalent".
- **`/api/stats` exposed per-arm counts during the test.** `/experiment`
  and the interim brief were blinded, but the API (by design, "counts, never
  a p-value") let anyone compute the running A-vs-B split. The counts were
  seen once, on 2026-10-09, shortly before the decision to stop early.
  **Fixed (2026-10-09):** `/api/stats` now returns pooled counts until the
  stopping rule is met, using the same rule as the status page.

## Dashboard layout test: decision brief

*Experiment `exp001_demo` · data Oct 3 to Oct 7, 2026 (4.1 days) · generated Oct 9, 2026 (UTC)*

> **Synthetic demo data.** 200 of 226 visitors were generated by `analysis/synthetic_traffic.py` with a known, hand-set effect. This brief demonstrates the pipeline and the reporting; it is not evidence about real users.

### The question

Does putting the charts first (the trend and the sector ranking), instead of the KPI tiles, get more people to drill into the rows behind a number? Drilling in is the measure of whether the dashboard invites a second question. The measure, the sample size and the decision rule were fixed before any data arrived (`docs/experiment_design.md`).

### Bottom line

**Adopt layout B (charts first).** Putting the charts first raised the share of visitors who drilled into the data from 37% to 56%, a gain of 19 points.

### The evidence

|  | Layout A (tiles first) | Layout B (charts first) |
|---|---|---|
| Visitors | 108 | 118 |
| Drilled into the data | 40 | 66 |
| **Rate** | **37.0%** | **55.9%** |

- **Difference:** +18.9 pts for B. Plausible range, given the sample: +6.1 pts to +31.7 pts.
- **Could it be chance?** If the layouts truly performed the same, a gap this large would show up about 1 time in 224. The bar set in advance was 1 in 20.
- **Sensitivity:** with this many visitors the test reliably detects differences of 19 points or more.

### How far to trust it

- **Traffic split:** 108 / 118 visitors (A / B). Consistent with the planned 50/50.
- **Event integrity:** every click traces back to an exposed visitor.
- **Sample:** 108 visitors in the smaller layout against a plan of 250.
- **Audience:** visitors to a portfolio site, mostly recruiters and peers. The result describes this audience, not every dashboard user.
- **What it measures:** whether people dig into the data, which is engagement, not proof of usefulness. A layout that answers the question faster could lower it.
- **Not checked:** page speed and error rates were not instrumented, so the decision has no guardrail against a layout that is slower or breaks.

### How each layout was used (exploratory)

Context for the decision, not part of it. These cuts were not the test's question, so a difference here is a lead for the next experiment, not a finding.

|  | Layout A | Layout B |
|---|---|---|
| Drilled into the data | 37% | 56% |
| Median time to first click | 1 s | 1 s |
| Kept exploring (of those who drilled in) | 48% | 48% |
| Came back | 22% | 19% |
| Median time on page (visible) | 46 s | 42 s |
| Quick exits (< 10 s, no drill) | 6% | 10% |

First clicks by element:

| Element | Layout A | Layout B |
|---|---|---|
| Small multiples | 32% | 32% |
| Sector ranking | 22% | 30% |
| Sector table | 20% | 23% |
| Trend chart | 25% | 15% |

### Recommended next step

Roll out layout B, then confirm with a follow-up test that adds the page-speed and error guardrails this one lacked.
